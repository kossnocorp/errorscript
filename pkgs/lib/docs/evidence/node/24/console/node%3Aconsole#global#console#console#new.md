## Conclusion

All constructor effects here are **synchronous**. Intrinsic validation errors are:

- `TypeError`: `ERR_CONSOLE_WRITABLE_STREAM` (missing/non-callable stdout/stderr `.write`), `ERR_INVALID_ARG_VALUE` (colorMode not `auto`, true or false), `ERR_INVALID_ARG_TYPE` (non-number indentation or invalid inspectOptions object), `ERR_INCOMPATIBLE_OPTION_PAIR` (defined inspect colors plus explicitly defined colorMode).
- `RangeError`, `ERR_OUT_OF_RANGE`: non-integer indentation, NaN/infinities, or outside inclusive `[0, 1000]`.
- Uncoded `RangeError`: diagnostic inspection recurses indefinitely between two normally returning custom hooks. This is recursion in Node's diagnostic traversal, not a hook throwing RangeError or an already-exhausted caller stack.
- `ReferenceError`: reading uninitialized native module namespace bindings during options discrimination/destructuring, stream `.write` validation, inspectOptions `.colors` validation, or diagnostic constructor-name lookup.
- Exact base `Error`, `ERR_INTERNAL_ASSERTION`: namespace diagnostic formatting catches an exported object's custom-inspection exception, expects a native ReferenceError, and creates an internal assertion error when the caught value fails that check.
- Uncoded `TypeError`: null/undefined inspect-map entries at `.colors`, revoked/invariant-violating proxies, malformed diagnostic constructor metadata, detached null-prototype typed-array reconstruction or malformed collection iterator results during diagnostics, non-callable subclass method overrides, failed strict assignment/property definition or missing internal helpers on an alternate prototype.

Options/stream/inspect-map property reads, proxy traps, diagnostic custom inspection and collection iteration, and subclass accesses/binding/setters/helper calls can propagate **any JS value**. Tests separately demonstrate supplied `Error`, supplied `SyntaxError`, and non-Error identity. The namespace test additionally proves a **created**, not propagated, Error. No intrinsic SyntaxError parser branch was established. Custom code can reject promises, emit events, or schedule work, but those independent effects are not a new constructor rejection/event channel. Native construction neither writes to streams nor returns a promise. The inspectOptions map uses a native iterator rather than a supplied iterator; **diagnostics are different** and may invoke supplied Set/Map iterators synchronously. Neither iteration path is deferred to the caller. Async fixture loading finishes successfully; ReferenceError is caught inside the synchronous Console call.

Assumptions: unmodified Node primordials, Console prototype, util.inspect defaults, and normal engine operation (no OOM/termination or arbitrary global monkey-patching). Supplied subclasses and structural/proxy inputs are **not** assumed benign. No stdio/TTY capability or functioning output sink is required: construction checks `.write` but does not call it. `ignoreErrors` only becomes a Boolean property and does not suppress constructor exceptions. There are no OS/inspector/color-detection branches in this constructor; auto-color probing belongs to later logging. Node's diagnostic HideStackFramesError constructor can itself leave `Error.stackTraceLimit` at zero on abrupt message generation. All capture helpers and native fixtures now restore the **original descriptor** in `finally`; this is teardown, not a change made to force a failure.

Existing `subs/errs/tools/gen-libs/errs.mjs:4–16,31–40` marks DOM/WebWorker Console **methods** as `Returns<..., never>`. That logging policy cannot be extended to this Node constructor: even inert ordinary objects reach unconditional validators, and custom hooks are observable. No existing annotations were changed.
