## Conclusion

Calling the saved built-in does not synchronously throw under ordinary resource assumptions: it is an async function. Intrinsic failures become **promise rejections**:

- **TypeError**: nullish receiver; absent internal state on incompatible receivers; revoked/invariant-violating receiver proxies; non-callable `close` (`ERR_INVALID_ARG_TYPE` only when diagnostic construction succeeds). Diagnostic/warning inspection can itself create uncoded TypeError, e.g. reconstructing a detached null-prototype typed array.
- **RangeError**: appending the close callback to a supplied receiver's full sparse listener array; also native inspection recursion through mutually returning custom-inspection objects during invalid-close diagnostic or warning construction. These are built-in-created failures, not values thrown by the fixture hooks.
- **ReferenceError**: invalid-close diagnostic reads a native module namespace's still-uninitialized `constructor` export; warning inspection can reach the same failure through namespace property-descriptor lookup. Both occur inside the disposer and reject its promise.
- **Error**, `ERR_SOCKET_DGRAM_NOT_RUNNING`: a `newListener` listener closes the real socket while the disposer registers its close callback, before `close` performs its health check.
- **Error**, `ERR_UNHANDLED_ERROR`: with EventEmitter captureRejections enabled, a returned thenable's `then` getter throws a non-Error value while registering the close listener, and no `error` listener handles it. The generated Error retains that supplied value in `.context`.
- **Error**, `ERR_INTERNAL_ASSERTION`: diagnostic/warning inspection of a function whose non-string name is a module namespace reaches namespace formatting; a nested custom-inspection failure other than ReferenceError is replaced by Node's internal assertion Error.
- **Arbitrary supplied values**, including SyntaxError, from getters/proxy traps and synchronously invoked `newListener` callbacks. SyntaxError in the repro is propagated, not created by the disposer.

An ordinary unbound/bound socket closes successfully; a socket with null handle immediately fulfills (including a second call before the scheduled close event). Arguments are ignored: no argument validation, coercion, iteration or iterator-time channel. Native close does not convert an OS status into a disposal rejection.

**Deferred event delivery is not promise rejection.** `close` is emitted on nextTick. A throwing close listener propagates on that event stack; if it precedes the promisify callback, that callback is not reached and the disposal promise can remain pending. When disposal is queued behind a bind, duplicate queued closes can throw `Error[ERR_SOCKET_DGRAM_NOT_RUNNING]` during `listening` delivery while both disposal promises subsequently fulfill from the first close event. Bind/lookup errors belong to the already initiated operation's `error` event, not to disposal rejection; bind failure discards the queue and can leave disposal pending until a later explicit close. Earlier queued send/connect operations and their listeners retain their own callback/event effects; disposal neither awaits nor rejects on those errors.

Scope: Node 24.19.0, normal native socket state and unmodified built-ins, live process, no OOM/termination or deliberately corrupted private symbols/native handles. Receiver proxies (including synthetic `_events`), public listener registration/captureRejections, and supplied inspection hooks are included. Recoverable engine stack-limit RangeError from native inspection recursion is included, not excluded as OOM. Arbitrarily replaced close implementations, custom promisify functions and their getters have unknown supplied-code effects, not an invented finite intrinsic error list. User async-hooks/domain instrumentation and global monkey-patching are outside this per-callable contract.

### Review correction: registration, diagnostic construction and inspection

The original warning-only statement in proof point 5 describes **successful construction and scheduling** of a warning, not an exclusion of errors while constructing it. The earlier nine-case conclusion missed reachable intrinsic errors. Comparison with `node:cluster > Cluster > addListener` evidence identified the shared `_addListener` path; the following primary-source proof and six added tests supersede that incomplete analysis. **Registration RangeError.** [`events.js:565–595`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/events.js#L565-L595) executes `existing.push(listener)` for an existing listener array, before warning construction.
