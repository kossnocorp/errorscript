The `assert` namespace merges with the exported assertion function (6–15,1110); `node:assert` re-exports it (1112–1115). - Runtime mapping: `assert.AssertionError` → `lib/internal/assert/assertion_error.js` class `AssertionError extends Error`, constructor at 249–386. `lib/assert.js:55,208` imports and exports that class.
- Status: complete (behavioral evidence, not annotation delivery).
- Contract candidate: `Returns<AssertionError, unknown>`. More precisely, the synchronous error component includes intrinsic `TypeError | RangeError | ReferenceError | Error` plus dependent effects of options/prototype/getter/proxy access, coercion, diagnostic inspection/iteration, and stack formatting. Those effects may throw **any JS value**; a finite built-in union alone is unsound. `Throws<F>` requires a callable operand, not an error-class union.

## Conclusion

Construction normally **returns** an `AssertionError`; it does not throw the error it creates. Intrinsic failures established for Node 24.19.0:

- `TypeError`: invalid options (`ERR_INVALID_ARG_TYPE`), calling the class without `new`, revoked/inconsistent proxies, failed string/property/numeric conversions, malformed `details`, invalid iterators encountered during inspection, detached typed-array reconstruction, failed instance writes/property definitions or stack capture with a supplied construction prototype.
- `RangeError`: Node recursively copies Error-valued `cause` without cycle detection. A self-cause on an Error, with another Error as the comparison operand, overflows in the constructor's own algorithm. Invalid-options diagnostic custom inspectors can also return each other's objects indefinitely.
- `ReferenceError`: the options namespace's requested export is still uninitialized; the read occurs inside construction.
- Exact public base `Error`, code `ERR_INTERNAL_ASSERTION`: formatting a module namespace catches an unexpected nested inspection failure and converts it into an internal assertion error.
- Arbitrary propagation: options accessors/traps, validation diagnostics, message/operator coercion, error copying, special inspection properties, Map/Set iteration (including `return`), internal-details reads/coercion, supplied new-target/prototype hooks, and the supported `Error.prepareStackTrace` hook. Separate Error and SyntaxError identity repros demonstrate propagation, **not** intrinsic creation of SyntaxError.

All these effects are **synchronous**. Iterators used for diagnostics are consumed/closed inside the call, not returned for deferred execution. Promise inspection reads internal state without awaiting or rejecting a new promise. There is no error-first callback or `error` event. One environmental side effect is possible: conflicting color environment settings can schedule a process **warning event** (see below); arbitrary warning-listener failures are later event-delivery effects, not synchronous constructor throws.

Scope: Node **v24.19.0**, Linux x64, V8 **13.6.233.17-node.51**, ordinary initialized host/stdio and unmodified primordials/inspection defaults. Supported stack-formatting customization and supplied object/prototype hooks are explicitly included. No arbitrary replacement of built-ins, startup-snapshot creation, OOM/process termination, pre-exhausted caller stack, or hostile global prototype mutation is used. Algorithmic recursion from small cyclic input is included. Other Node versions need rechecking; browser APIs are not involved. Platform color-selection branches change formatting, not the identified intrinsic classes under a normally functioning host.
