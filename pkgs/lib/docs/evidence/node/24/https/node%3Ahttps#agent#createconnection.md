## Conclusion

Verified synchronous conditions: invalid receiver, invalid `checkServerIdentity`,
invalid TLS version, too-small `minDHSize`, malformed certificate, unavailable cipher,
and an uninitialized module-namespace `port` export. Getter and proxy failures
propagate supplied values unchanged. The ReferenceError is generated by a binding
read **inside** this method, not by constructing or evaluating an argument.

Verified deferred delivery: a local proxy's 502 response produces
`Error`/`ERR_PROXY_TUNNEL` through the optional callback. A local peer ending before
the TLS handshake produces `Error`/`ECONNRESET` on the returned socket's `error`
event; the direct branch ignores the optional callback. The native function
returns a socket, not a promise or iterator. Test promises only bridge event/callback
delivery; these are not `.rejects` effects of `createConnection` itself.

Scope: stock Linux Node 24.19.0 with bundled OpenSSL 3.5.7, no monkey-patching;
ordinary runs without diagnostic environment settings. Startup diagnostic flags,
alternative crypto/platform builds, supplied streams, and TLS handshake callbacks
remain important open branches, **not exclusions from a purported complete contract**.

### Dispatch, receiver, and arbitrary effects

[`lib/https.js:332–443`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/https.js#L332-L443)
also accepts legacy `(port, host, options)` at runtime. The first object is used
directly; an object in the second/third position is spread. Numeric port and string
host are written to options, and the final function argument becomes `cb`.
There is no encompassing catch. Relevant operations include:

- `options._agentKey` and session-cache method/property access (357–367).
- `getTunnelConfigForProxiedHttps(this, options)` (371), whose first access is
  `agent[kProxyConfig]` at 165: an undefined receiver throws TypeError before TLS.
- The template expression `...${options.host}:${options.port}:` at 372 is evaluated
  even if debug output is disabled. Getters and primitive conversion may throw.
- `socket = tls.connect(options)` (375); its options spread at
  [`wrap.js:1832–1852`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/internal/tls/wrap.js#L1832-L1852)
  reaches a proxy's `ownKeys` trap. The test proves identity propagation with a Symbol.
- Session/close handlers at 429–439 call cache methods later. Those effects are
  not necessarily synchronous with creation.

These operations also explain why valid TypeScript types cannot justify a closed
finite exception list. The getter test throws an object from `_agentKey`; no socket
has yet been created. The proxy test throws before TLS context/socket allocation.

### Callback and event channels

[`https.js:164–214,374–424`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/https.js#L374-L424)
selects a proxy according to agent configuration and request host/port. The HTTP
proxy branch uses `net.connect`, whereas an HTTPS proxy uses `tls.connect`.
[`217–327`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/https.js#L217-L327)
parses CONNECT responses: `statusCode !== '200'` creates `ERR_PROXY_TUNNEL`, sets
`statusCode`, and calls `afterSocket(err, socket)`. Cleanup at 390–408 ultimately
does “cb(err, currentSocket)”. [`errors.js:1678`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/internal/errors.js#L1678)
registers this as Error. Local 502 response proves this callback-delivery branch.
Callback exceptions have no catch here and would escape in the later event turn;
callback-thrown identity is not yet runtime-tested. Proxy EOF/timeout also construct
this code (298–315,385–388); proxy success starts TLS later (272–293), so TLS setup
throws on that path can occur **after** the initiating call returned.

Direct TLS uses `tls.connect(options)` without `cb`. Its
[`onConnectEnd`, wrap.js:1815–1828](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/internal/tls/wrap.js#L1815-L1828)
constructs `ConnResetException` and calls `this.destroy(error)` if the connection
ends before verification. [`errors.js:833–842`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/internal/errors.js#L833-L842)
sets `code = 'ECONNRESET'` and explicitly exposes `Error` through its constructor
getter. The event repro checks that public constructor and code, not merely
`instanceof Error`. It also verifies no direct-branch optional callback invocation.

Additional source-established supplied-code channels needing repros:
[`net.js:1600–1662`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/net.js#L1600-L1662)
calls `options.lookup` during connect (its synchronous throw can escape);
[`wrap.js:1772–1794`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/internal/tls/wrap.js#L1772-L1794)
calls `checkServerIdentity` after handshake without a surrounding catch, but a
returned verification error is passed to `destroy`;
[`518–550`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/internal/tls/wrap.js#L518-L550)
catches PSK callback/validation failures and calls `owner.destroy(err)`.
These distinctions preclude treating every callback effect as synchronous throw.

## Open questions / precise blocker

This is a partial primary-source audit, **not an exhaustive proof**. Completion
requires closing these reachable branches and supplying deterministic repros:

1. All remaining `configSecureContext` native calls (key/CA/CRL/PFX, DH/ECDH,
   sigalgs, engine/permission/build branches, ticket/session options, compression),
   `TLSSocket` setup/native TLSWrap, ALPN conversion, session reuse/serialization,
   certificate translation, and net/stream/AbortSignal validators. No conclusion
   excluding SyntaxError or additional intrinsic classes has been proved.
2. Supplied socket/JSStreamSocket, custom lookup, coercions, cache key/property
   traps, session/close callbacks and caller mutations. Validate exact channels
   and supplied-value identities, including deferred callback exceptions, without
   leaking hidden sockets or crashing the main Vitest worker.
3. Proxy exclusion, HTTPS proxy handshake, successful CONNECT followed by failing
   TLS setup, early EOF/timeouts, and status/endpoint validation. These do not reduce
   to the direct-TLS synchronous path. Only HTTP-proxy 502 has a deterministic repro.
4. Diagnostics and error formatting: HTTPS calls debug before validation;
   [`debuglog.js:65–75`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/internal/util/debuglog.js#L65-L75)
   calls `formatWithOptions` when enabled. `inspect.js:800–825,2003–2018` catches
   namespace ReferenceErrors and asserts particular error shapes;
   [`internal/assert.js:8–12`](https://github.com/nodejs/node/blob/cdc1b38d40cb567b7ad0b39c86addf830a0af0ae/lib/internal/assert.js#L8-L12)
   can throw `ERR_INTERNAL_ASSERTION`. Formatting can also invoke supplied custom
   inspect code. This graph has not been exhaustively checked/reproduced; do not
   assume the verified namespace case covers all diagnostic paths.

No shared configuration/dependency change is requested for the existing repros.
Further isolated child-process fixtures may be needed for deferred uncaught throws
and startup diagnostics. Node annotation delivery remains coordinator-deferred.
